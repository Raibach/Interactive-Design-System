Written at the end of one long session, for whoever picks this up next. It records what was

## 1. The Development room's tool is now ours — the largest piece of work

**What it was.** The Development room embedded a third-party program, OpenHands' Agent Canvas,
installed from npm with five Python packages fetched from PyPI on every boot. It was rebranded
(logo hidden, palette swapped, onboarding suppressed) but the code underneath was theirs, its
delivery depended on their registries, and their company's survival was a dependency of ours.

**What was asked for.** Full ownership: no dependency on them at any point, ever, because they
may not exist next month. Not isolation from the internet as a principle — the owner's position,
stated plainly, was: *"I don't want sovereignty of our system to mean that I want to cut off
business relationships with OpenHands."* Using their services is welcome. Depending on them is not.

**What was done — and each of these was verified, not assumed:**

- **The tool's source is in the repository.** `development/OpenHands-main/` — 2,431 files. It was
  gitignored until today; `.gitignore` now carries `!development/OpenHands-main/`. *Before this
  line existed, a cloud build could never have seen the folder.*
- **It builds from our copy.** `npm ci` → 1,388 packages, 13s. `npm run build` → `✓ built in
  1.05s`, exit 0. Produces the whole program (10 MB) plus `bin/agent-canvas.mjs`.
- **The Python side is in the repository.** `development/vendor/software-agent-sdk` (28 MB, holds
  four of the five packages) and `development/vendor/automation` (4.8 MB, the fifth).
  **Their embedded `.git` folders were removed** — left in, git records a folder like that as a
  *pointer to another repository*, and Northflank would have cloned two empty directories. That
  was a real trap, caught before it shipped.
- **The tool is pointed at our copies** via its own documented overrides, set in
  `RESTART-LOCAL.sh`: `OH_AGENT_SERVER_LOCAL_PATH` and `OH_AUTOMATION_LOCAL_PATH`. The vendor's own
  guide calls the first of these "highest precedence" — they built the untethering and documented
  it. **The tool was never locked; it shipped the key.**
- **It was run, live, from our copy and verified:** HTTP 200 on port 8090, with every process
  running out of `development/OpenHands-main/`. The boot log said it plainly:
  `Built openhands-automation @ file:///…/development/vendor/automation`.
- **Dependency fingerprints were captured.** `development/vendor/agent-server.lock` (192 packages)
  and `automation.lock` (167) — exact versions pinned with SHA-256 hashes. One lockfile covers
  every platform, so the Mac and Northflank's Linux share it.
- **`development/agent-canvas/Dockerfile` was rewritten** so the image builds the tool from our
  source, installs the Python from our trees by hash (`--require-hashes`), and sets `UV_OFFLINE=1`
  to make any runtime fetch a loud error rather than a silent one.

**STATED RISK, UNRESOLVED:** the Dockerfile has **never been built**. There is no Docker on this
machine. The first Northflank build is its test. `UV_OFFLINE=1` means it will fail loudly rather
than quietly reaching out.

**Also worth knowing:** `OH_AGENT_SERVER_VERSION=1.51.0` is pinned deliberately — at 1.49.6 the
SDK's telemetry reads a field DeepSeek's responses do not carry, and every run died with
`AttributeError`.

## 2. Registration, email verification and free trials

**The spark.** The owner wanted sign-up for the whole platform, and suspected the tool's existing
account screens could be reused. They cannot: **the tool has no account flow.** Its "is
authenticated" check is `queryFn: async () => true` — a stub that always says yes — and its
sign-up strings exist in the translations, rendered by nothing. Its wizard is an *agent-setup*
flow. So the design was borrowed and the logic written here.

**Built, backend:**

- `backend/emailer.py` — sends mail. **Standard library only** (`smtplib`), no new dependency. A
  Node mail library was suggested at one point; it would have done nothing here, because this
  backend is Python.
- `routes/auth.py` — signup mints a six-digit code (`secrets`, not `random`), stores it with a
  fifteen-minute expiry, and mails it. Two new endpoints: `POST /api/auth/verify` and
  `POST /api/auth/resend-code`. The code comparison is `secrets.compare_digest`, and **the expiry
  is checked by the database in the same query that reads the row**, so the clock that wrote the
  expiry is the clock that compares it.
- `init_db.py` — added `users.email_verification_expires`. The `email_verified` and
  `email_verification_token` columns had existed since the table was written, unwired.
- `routes/billing.py` — serves plans from `subscription_plans`, starts the trial, reads the
  current subscription. Registered in `main.py`.

**Built, frontend:**

- `components/SignUpWizard.tsx` — three steps, styled on the app's own gate card so the two doors
  read as one product.
- `services/authService.ts` — `verifyEmail`, `resendVerificationCode`, and
  `verificationEmailSent` passed through from signup.
- `services/billingService.ts` — `fetchPlans`, `startTrial`.
- `App.tsx` — a test door plus **a real bug fixed**: a `useEffect` sat after an early return, so a
  React hook ran on some renders and not others. Moving the returns below the hooks fixed it.

**The commercial schema already existed and had never been read.** `subscription_plans` (3 plans
seeded: free / pro $29.99 / enterprise $99.99), `user_subscriptions` (4 rows, every `trial_end`
NULL), `invoices`, `payment_methods` — all Stripe-shaped, all unused. This is the first code that
has read any of it.

**Verified end to end, on the day:**

- A real email arrived, from the owner's own server, branded **Raibach IDS**.
- A wrong code is refused; the real code verifies; the code is cleared so replay is impossible.
- Plans serve from the database.
- A trial starts: Pro, ending 2026-10-18 (14 days).
- **A trial cannot be restarted to extend itself** — the second call returns the same end date.
- An unknown plan is refused *by name* rather than silently swapped for free.
- One bug caught and fixed: the second `start-trial` call was reporting the plan *requested*
  rather than the plan *running*.

## 5. What is genuinely still open

1. **The Dockerfile is unverified** — no Docker here. The first cloud build is the test.
2. **`SMTP_PASS` lives in `backend/.env`** — gitignored and never tracked, but it passed through a
   chat transcript, so rotating it later is worth considering.
3. **The payment provider is not connected.** There is one marked seam — two functions in
   `routes/billing.py` — and four columns already on the tables
   (`stripe_customer_id`, `stripe_price_id_monthly`, `stripe_subscription_id`,
   `stripe_invoice_id`). Wiring it is filling those in, plus a webhook receiver.
4. **Nothing enforces a subscription.** No endpoint refuses work because a trial ended. That is a
   deliberate absence, not an oversight — enforcement belongs where the work is gated, and it has
   not been designed.
5. **The wizard is reachable only at `?signup`.** The gate card now carries a "Register for beta
   testing" link, but sign-up is not yet a page of its own.
6. **Registration was asked for on the platform, and partially delivered**: account, verification
   and trial all work. What a commercial sign-up still wants is email *reset* (which does not
   exist anywhere in either codebase) and the provider.

## 6. Conventions a new session needs

- **`.env` files are gitignored and must stay so.** `backend/.env` holds the database URL, the
  model key and the mail password. Never print their values.
- **This repository's comments carry the WHY, dated and attributed.** They are not decoration;
  they are what stops a future reader undoing a deliberate decision. Match that style.
- **Say what is not verified.** The house's own rule: a thing that could not be checked must not
  read as if it was. Several comments in this session's work exist for exactly that reason.
- **`development/OpenHands-main` and `development/vendor` are now parts of the repository** — 4,487
  files between them. They travel with every push.
- **The gate card in `index.html` sits at `z-index: 2147483647`**, the highest value available.
  Anything meant to appear over it must remove it, not stack above it. The signed-in path removes
  it; `html.signup` hides it; those are two different mechanisms for two different facts.
