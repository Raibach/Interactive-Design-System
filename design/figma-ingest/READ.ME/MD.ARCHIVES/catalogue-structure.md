# The catalogue, and what to call each part

The owner, 2026-09-28: *"I keep saying catalogue, but for me that represents the components,
patterns, element styles, modules. But I may be using the wrong word — it may be the registry."*

**You are using the right word.** The **catalogue** is the whole thing. "Registry" is the
confusion in this repository: **three different files are called some version of "registry"**, and
none of them is the whole. This file draws what exists and names each part once.

## 2. Your words, mapped onto the real things

| Your word | The real thing | Where it lives |
|---|---|---|
| **elements** | the Lit web components | `frontend/src/components/lit/**.ts` |
| **styles** | design tokens, and each element's shadow CSS | `frontend/src/shared/design-tokens.ts` |
| **patterns** | compositions — today they are *names in the catalog* that map to an element (`COMPOSITE_MAP` in the renderer); they are not a separate artifact yet | the catalog's components |
| **modules** | one `.ts` file per element — and the manifest calls them modules too (44 of them, 69 declarations) | `custom-elements.json` |
| **catalogue** | **all of it, for one design system** | the pieces above, together |
| **registry** | ambiguous: it is the **allowlist** in the repo's own documentation, but `registry.json` is the **Figma map**, and the license plate on the whole thing (`registry.json` again) is what your AI instructions call "THE FIGMA MAP" | see the three below |

The one thing genuinely missing from your list: **the record** — the ledger of what was done to
this catalogue, which is what makes it governable and is the newest part.

## 3. "Registry" — stop saying it, and say which one

The repository says this itself, in `shared/tag-registry.ts`:

> Three files in this repository are called some version of "registry". This is the one that
> gates the AI. The other two are NOT this.

So the vocabulary to use, everywhere, including the tree UI and the plan documents:

| Say this | Not this | It is |
|---|---|---|
| **the allowlist** | "the registry" | `shared/tag-registry.ts` — name → tag, what may be rendered and emitted |
| **the Figma map** | "the registry" | `components/registry.json` — which Figma node each component came from |
| **the schema** / **the catalog** | "the registry" | `A2UI/catalogs/<id>/catalog.json` — what the server accepts |
| **the manifest** | — | `custom-elements.json` — what the elements actually declare |
| **the catalogue** | — | one design system's whole system-of-record |

## 4. What has no home yet, and where it goes when there are several catalogues

- The **allowlist**, the **Figma map**, the **schema** and the **manifest** are all
  single-instance today; per catalogue they each become one file per catalogue, named in that
  catalogue's descriptor (`multiple-catalogs.md` §3).
- The **manifest** is the odd one: it is generated per package by `cem analyze`, so a catalogue
  whose elements live in another package has its own manifest — which is also why the gate for a
  foreign catalogue compares declarations against *that* manifest, not the app's.
- The **record** needs its `catalog_id`, or a ledger spanning two catalogues can't be governed.

## 5. Verified 2026-09-28: there is a fourth registry file, and it is a copy

`find src -iname "*registry*"` returns **five** files, not three:

| File | What it is | Read by |
|---|---|---|
| `src/shared/tag-registry.ts` | **the allowlist** — may it be drawn, may the AI emit it | `lit/a2ui-renderer.ts:37` (`@/shared/tag-registry`) |
| `src/components/registry.json` | **the Figma map** — where it came from | the ingest/approval path |
| `A2UI/catalogs/<pipeline>/catalog.json` | **the schema** — will the server accept a payload | `backend/deps.py` → `validate_a2ui_components` |
| `src/components/lit-v2/shared/tag-registry.ts` | **a byte-identical copy** of the allowlist (same md5 `25b3fa9a…`) inside a dead tree | nothing — `lit-v2/` is referenced by nothing outside itself, and even its renderer imports `@/shared/tag-registry` |
| `src/shared/error-registry.ts`, `src/shared/storybookDocRegistry.ts` | unrelated namesakes (error messages, docs) | their own callers |

**The copy is a trap, not a hazard.** It changes nothing today — but its own header reads
"THE ALLOWLIST frontend/src/shared/tag-registry.ts ← you are here", so anyone who opens it to
add a component edits a file that decides nothing. Delete `src/components/lit-v2/` before the
second catalogue work starts, or move it somewhere that cannot be mistaken for the live tree.
