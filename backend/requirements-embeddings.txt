# The embedding model, for a machine that actually runs it. NOT for the container.
#
#     pip install -r requirements.txt -r requirements-embeddings.txt
#
# WHY THIS IS A SEPARATE FILE (2026-09-29). `sentence-transformers` pulls torch, and torch on
# Linux pulls the CUDA stack whether or not the machine has a GPU. Measured inside the
# production image before this split:
#
#     site-packages   6.2 GB total
#       nvidia        3.2 GB
#       torch         1.2 GB
#       triton        897 MB
#       transformers  118 MB
#       scipy         113 MB
#       sympy          80 MB
#       sklearn        51 MB
#       (pandas, pyarrow, faiss-cpu and numpy stay — `pymilvus` and `milvus-lite` need them)
#
# So roughly 5.5 GB of an image that is capped at 512 MB of memory and can never load any of
# it. The models were an attempt at local embedding; the system runs on a hosted model and does
# not embed in the container.
#
# INSTALLING THIS ON A DEPLOYMENT IS A REGRESSION, not a neutral act: it adds ~5.5 GB to the
# image, to a build, and to every deploy that follows, in exchange for a model that instance
# cannot load. If embedding is ever wanted close to production again, the cheaper shapes are a
# CPU-only torch (`--index-url https://download.pytorch.org/whl/cpu`, about 200 MB instead of
# 1.2 GB plus the CUDA stack) or an embedding API — and either is a decision to make on purpose.
#
# WHAT IT COSTS WHERE IT IS MEANT TO RUN
#   - about 1.2 GB of site-packages, and roughly 500 MB-2 GB resident once the model is loaded
#   - the model weights (BAAI/bge-small-en), cached on disk after first use, so no network at
#     first call thereafter
#   - zero model tokens: embeddings are computed locally, which is why this exists at all
